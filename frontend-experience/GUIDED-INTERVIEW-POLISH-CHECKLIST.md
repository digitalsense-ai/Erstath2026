# Guided AI Interview - Polish Checklist

Version: 0.1  
Purpose: A practical checklist for improving the Guided AI Interview prototype until it feels calm, trustworthy and human.

---

## A. Overall feeling

1. Does the experience feel more like a conversation than a form?
2. Does the user feel that the system has read their first text?
3. Does the first AI response create trust?
4. Does the user understand what to do next without thinking?
5. Does the page feel calm within the first three seconds?
6. Does the interface avoid looking like a legal system?
7. Does the product feel different from a normal chatbot?
8. Does the user see that the case is being built?
9. Does the user feel in control?
10. Does the flow avoid pressure or urgency?

## B. Wording

11. Replace technical words with everyday Danish.
12. Avoid saying "case" too early when "forløb" is softer.
13. Use "undersøges nærmere" instead of strong legal conclusions.
14. Avoid wording that implies a final assessment.
15. Make every question sound helpful, not administrative.
16. Keep AI messages short enough to scan quickly.
17. Start with recognition before asking new questions.
18. Use "cirka" when precision is not required.
19. Use "Det er okay, hvis du ikke ved det" where relevant.
20. Avoid repetitive phrases across multiple AI messages.

## C. AI thinking state

21. Thinking text must be short and human.
22. Avoid technical words such as "analyserer", "klassificerer" and "modellering".
23. Use phrases like "Jeg læser lige det, du skrev".
24. Use phrases like "Jeg samler det i almindeligt dansk".
25. The thinking state should feel reassuring, not slow.
26. The loader should not stay visible too long.
27. The thinking note should disappear or fade softly.
28. The thinking note must never reveal internal reasoning that sounds uncertain or mechanical.
29. The user should feel the system is careful.
30. The typewriter effect should be calm, not distracting.

## D. Chat layout

31. AI messages must always appear on the left.
32. User messages must always appear on the right.
33. The chat should scroll internally on desktop.
34. The answer area should remain visible at the bottom.
35. The page itself should not require scrolling on desktop.
36. Chat bubbles should not become too wide.
37. Long AI text should be broken into readable sections.
38. The spacing between messages should feel calm.
39. The avatar labels should be clear but subtle.
40. The top header should not steal vertical space.

## E. Answer buttons

41. Buttons should feel like helpful suggestions, not categories.
42. There should normally be 2-4 main options plus fallback choices.
43. Always include "Jeg kan ikke huske" when memory may be an issue.
44. Always include "Skriv selv" or similar escape option.
45. Avoid too many buttons in one row.
46. The primary option should not feel forced.
47. Button wording should match how a normal person speaks.
48. Buttons should be easy to tap on mobile.
49. Hover and focus states should be visible.
50. Selected answers should be reflected in the chat.

## F. Right panel / living summary

51. The panel should be called "Sådan forstår jeg dit forløb".
52. It should not look like a database form.
53. It should use plain Danish sentences.
54. It should clearly separate understood from missing.
55. It should reassure that everything can be corrected.
56. It should update after each user answer.
57. It should not create anxiety with too many missing items.
58. Missing items should be framed as "det jeg stadig mangler".
59. The next question should be visible in the panel.
60. The panel should scroll internally if it becomes long.

## G. Colors

61. Keep the palette calm and limited.
62. Use dark blue for AI and core actions.
63. Use muted green for positive understanding and progress.
64. Avoid yellow unless there is a strong reason.
65. Use soft blue-green for explanatory boxes.
66. Avoid strong red in the early experience.
67. Make sure contrast is accessible.
68. The right panel should feel calm, not like a warning area.
69. The progress indicator should be subtle.
70. Colors should support trust, not decoration.

## H. Accessibility

71. Font sizes should work for older users.
72. Text should remain readable on small screens.
73. Do not rely only on color to show status.
74. Buttons need clear focus states.
75. The flow must be usable by keyboard.
76. Avoid dense paragraphs.
77. Use enough line height in chat bubbles.
78. Avoid moving elements that distract too much.
79. Typewriter animation should be disabled or simplified on mobile if needed.
80. The user should never lose context when scrolling.

## I. Trust and safety

81. Do not promise compensation.
82. Do not say the user has a case.
83. Do not make medical conclusions.
84. Say clearly that this is not a final assessment.
85. Explain why sensitive questions are asked.
86. Make it easy to say "I do not know".
87. Make it easy to correct earlier answers.
88. Avoid sounding like a government form.
89. Avoid sounding like a lawyer too early.
90. Reassure that the first goal is understanding.

## J. Product signature

91. AI should prove it has listened before asking more.
92. AI should never ask for something it already knows.
93. The user should click more than they write.
94. The right panel should make the user feel progress.
95. Every answer should make the case clearer.
96. The experience should feel guided, not automated.
97. The user should feel they can stop and return later.
98. The final summary should be in ordinary Danish.
99. The system should feel like it works with the user.
100. The product should leave the user feeling understood.

---

3. Make the right panel feel like a living understanding, not a status box.
4. Keep the answer area visible without page scrolling.
5. Make the AI thinking state reassuring and brief.
