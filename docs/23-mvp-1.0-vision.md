# 23 - MVP 1.0 Vision

## Purpose

This document describes the long-term product vision for ErstatningsHjælp beyond MVP 0.1 and MVP 0.2.

It should guide future planning without changing the scope of the current MVP.

MVP 0.1 remains focused on:

```text
AI Screening
Lead Storage
Internal CRM Review
Testing Foundation
Security Foundation
```

MVP 1.0 describes the direction for a more complete platform.

---

# 1. Vision statement

ErstatningsHjælp should become an AI-assisted platform that helps identify, qualify, structure and manage potential compensation-related cases more efficiently.

The platform should combine:

```text
low-friction user intake
AI-assisted screening
structured CRM workflows
case preparation support
secure data handling
human final review
business prioritization
```

AI should improve speed, structure and prioritization.

AI should not replace responsible human review.

---

# 2. Product position

ErstatningsHjælp should not be positioned as a simple contact form.

It should be positioned as a guided screening and qualification engine.

Traditional flow:

```text
Landing page
↓
Long form
↓
Manual review
↓
Slow qualification
```

Target flow:

```text
Landing page
↓
Short natural-language input
↓
AI-guided follow-up
↓
Structured scoring
↓
CRM prioritization
↓
Human review
↓
Case preparation
```

---

Capabilities:

```text
AI follow-up questions
one-question-at-a-time flow
screening summary
safe expectation setting
```

Capabilities:

```text
commercial value scoring

case category
recommended action
missing information detection
```

---

## Module 3 - Internal CRM

Purpose:

```text
Help internal users review and prioritize leads.
```

Capabilities:

```text

lead detail page
filters
status updates
assignment
internal notes
priority queues
```

---

## Module 4 - Qualification workflow

Purpose:

```text

```

Capabilities:

```text

missing material checklist
case lifecycle
review checklist
```

---

## Module 5 - Secure document readiness

Purpose:

```text
Support future material handling in a controlled way.
```

Capabilities:

```text
document checklist

safe storage architecture

```

---

```text

score calibration

quality feedback
```

```text
Make the platform maintainable, secure and reviewable.
```

Capabilities:

```text

consent records

```

# 4. Target user journeys

## User journey

```text
User lands on site
↓
User writes what happened
↓
AI asks relevant follow-up questions
↓
User receives safe next-step guidance
↓
Strong leads continue to deeper qualification
```

The public journey should feel simple, calm and trustworthy.

---

## Internal caseworker journey

```text
Caseworker logs in
↓
Views prioritized lead board
↓
Opens lead detail page
↓
Reviews summary, scores and missing information
↓
Updates status or assigns next step
↓
Moves qualified lead into deeper workflow
```

The internal journey should reduce manual reading and help focus on the strongest leads first.

---

## Admin journey

```text
Admin manages users
↓
Reviews audit and operational controls
↓
Monitors lead volume and quality
↓
Adjusts internal process with governance
```

---

# 5. Business model direction

The system should support a business model based on better lead qualification and case prioritization.

Potential business value drivers:

```text
higher lead conversion quality
less manual time spent on weak leads
faster response to strong leads
better documentation before human review
more consistent internal decisions
improved operational overview
```

The platform should measure:

```text
lead volume
qualified lead rate
rejection rate
manual review rate
average score by source
conversion from lead to case
caseworker workload
processing time
```

---

# 6. Technical target architecture

MVP 1.0 should evolve toward a modular Laravel architecture.

Suggested high-level modules:

```text
Lead module
Conversation module
AI module
Scoring module
CRM module
Auth and permissions module
Audit module
Consent/authorization module
Case lifecycle module
Reporting module
```

AI provider calls should remain isolated behind service classes.

Business scoring should remain deterministic where possible.

---

# 7. AI principles

AI should:

```text
assist
summarize
structure
prioritize
ask better questions
highlight missing information
```

AI should not:

```text
make final decisions
promise outcomes
bypass internal review
store unvalidated output as official truth
expose raw debug data to users
```

All AI output used by the system should pass validation or controlled transformation.

---

# 8. Compliance and trust principles

The platform should be designed around trust.

Core principles:

```text
data minimization
clear consent and authorization records
role-based access
auditability
safe logging
retention policy
human review
transparent user communication
```

The system should avoid collecting more data than needed for the current step.

---

# 10. What success looks like

MVP 1.0 is successful if the platform can:

```text
receive leads with low friction
screen leads consistently
identify stronger leads faster
reduce manual review time
support internal prioritization
track workflow status
support secure operations
provide useful business metrics
```

The platform should improve both user experience and internal efficiency.

---

# 11. What should remain protected

Even at MVP 1.0, the following principles should remain protected:

```text
human final review
no unsupported automated final decisions
no uncontrolled data collection
no raw AI exposure by default
no scope expansion without governance
no real secrets or real case material in repository
```

---

# 12. Strategic recommendation

The project should grow in layers:

```text
First prove screening.
Then improve internal workflow.
Then add readiness and qualification layers.
Then add deeper integrations only when the foundation is stable.
```

The most important product discipline is to keep MVP 0.1 small until it works.

Final vision:

```text
ErstatningsHjælp should become a secure AI-assisted intake and qualification platform that helps humans find and handle the strongest cases faster.
```
