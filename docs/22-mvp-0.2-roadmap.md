# 22 - MVP 0.2 Roadmap

## Purpose

This document defines the first post-MVP roadmap for ErstatningsHjælp.

MVP 0.2 should only start after MVP 0.1 has proven the core screening and CRM flow.

MVP 0.1 remains focused on:

```text
AI Screening
Lead Storage
Internal CRM Review
Basic QA and Security Foundation
```

MVP 0.2 may expand the product into deeper qualification and case preparation.

---

# 1. Important principle

MVP 0.2 must not contaminate MVP 0.1.

This means:

```text
Do not build MVP 0.2 features before PR-001 to PR-015 are working.
Do not change MVP 0.1 scoring or screening flow to support future ideas too early.
Do not add heavy integrations before the core flow is validated.
```

MVP 0.2 should be planned now, but implemented later.

---

# 2. MVP 0.1 baseline

Before MVP 0.2 starts, MVP 0.1 should have:

```text
Public screening start endpoint
Public screening continue endpoint
AI screening service
AI JSON validation
Deterministic scoring
Lead persistence
Internal authentication
Lead list API
Lead detail API
CRM lead board
CRM lead detail page
Lead status updates
Basic tests
Security review foundation
```

If these are not working, MVP 0.2 should not begin.

---

# 3. MVP 0.2 goal

MVP 0.2 should move the system from basic lead screening to structured case qualification.

The goal is to help internal users answer:

```text
Is this lead ready for deeper case handling?
What additional acceptance/authorization is needed?
Which documents or information are missing?
Who should handle the case internally?
What is the next operational step?
```

---

# 4. Proposed MVP 0.2 themes

## Theme 1 - User identity and verification preparation

Purpose:

```text
Prepare the product for stronger user verification later.
```

Possible scope:

```text
identity status field
verification readiness status
manual verification placeholder
integration abstraction
clear UI labels for not-yet-verified leads
```

Out of scope until approved:

```text
real external identity integration
production identity flow
```

---

## Theme 2 - Authorization and acceptance flow

Purpose:

```text
Track whether the user has accepted relevant terms or authorization steps for deeper handling.
```

Possible scope:

```text
authorization status
authorization versioning
acceptance timestamps
withdrawal concept
CRM visibility
simple internal checklist
```

Out of scope until approved:

```text
legally binding digital signing flow
external signing provider integration
```

---

## Theme 3 - Document readiness and metadata

Purpose:

```text
Prepare the system to understand which supporting material may be needed.
```

Possible scope:

```text
document checklist
metadata-only document records
required vs optional document types
CRM missing-material view
safe storage architecture plan
```

Out of scope until approved:

```text
active file upload
file processing
advanced document analysis
```

---

## Theme 4 - Case lifecycle foundation

Purpose:

```text
Move qualified leads into a more structured internal case lifecycle.
```

Possible statuses:

```text
qualified_lead
ready_for_review
accepted_for_casework
not_accepted
closed
```

This should remain separate from MVP 0.1 screening statuses until implemented.

---

## Theme 5 - Assignment workflow

Purpose:

```text
Allow internal users to assign leads or cases to a responsible person.
```

Possible scope:

```text
assigned_user_id
assignment timestamp
assignment history later
filter by assigned user
CRM ownership display
```

---

## Theme 6 - Internal notes

Purpose:

```text
Allow caseworkers to add structured internal notes.
```

Possible scope:

```text
lead notes
note author
note timestamp
note visibility
safe audit hook
```

Rules:

```text
Notes must be internal only.
Notes should not be visible in public screening flow.
Notes must avoid unnecessary sensitive details.
```

---

## Theme 7 - Advanced CRM filters

Purpose:

```text
Make CRM more useful once lead volume grows.
```

Possible filters:

```text
score range
category
status
recommended action
assigned user
created date
needs information
ready for review
```

---

## Theme 8 - Case intelligence preparation

Purpose:

```text
Prepare for later intelligence features without building them too early.
```

Possible future areas:

```text
similar case suggestions
pattern detection
outcome tracking
case value prediction
quality scoring improvements
```

Out of scope for MVP 0.2 unless separately approved:

```text
automated final decision
fully automated legal analysis
external submission automation
```

MVP 0.2 should strengthen:

```text
audit logging
role-based permissions
consent and authorization tracking
retention policy enforcement
safe internal notes
safe metadata storage
restricted access to deeper case data
```

No advanced flow should be implemented without reviewing:

```text
docs/09-security-gdpr.md
docs/18-architecture-governance.md
docs/20-data-dictionary-v2.md
docs/21-consistency-review.md
```

---

# 10. MVP 0.2 acceptance criteria

MVP 0.2 should be considered successful if:

```text
Qualified leads can move into deeper internal qualification
Internal users can see readiness status
Authorization and acceptance status can be tracked
Document readiness can be represented safely
Assignments and notes improve CRM workflow
No MVP 0.1 scope boundaries were broken early
Security and audit model remains consistent
```

---

# 11. What should wait until after MVP 0.2

The following should not be built in MVP 0.2 unless there is a separate approval:

```text
full external identity integration
legally binding signing integration
active file upload with processing
advanced automated document analysis
automated final legal decision
external authority submission
advanced outcome prediction
public user account portal
```

---

# 12. Recommended sequence

After MVP 0.1 is working:

```text
1. Review MVP 0.1 usage and lead quality
2. Decide which MVP 0.2 theme solves the biggest bottleneck
3. Create Epic 09 only when ready
4. Build one theme at a time
5. Keep advanced integrations behind clear boundaries
```

Recommended first MVP 0.2 theme:

```text
Assignment and Internal Notes
```

Reason:

```text
It improves internal workflow without requiring heavy external integrations.
```

Recommended second theme:

```text
Authorization Readiness
```

Reason:

```text
It prepares deeper handling while keeping implementation manageable.
```

---

# 13. Final recommendation

MVP 0.2 should be treated as a post-validation roadmap.

Do not start it before MVP 0.1 proves that the core AI screening and CRM review flow works.

Final rule:

```text
MVP 0.1 proves the lead engine.
MVP 0.2 improves qualification and internal case preparation.
Later releases add heavier integrations.
```
